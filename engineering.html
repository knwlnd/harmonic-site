Engineering

Built around repeatable musical behaviour.

This page explains the architecture conceptually without exposing private source code or internal APIs.

Instrument architecture

Harmonic separates user intent, tonal interpretation, harmonic derivation, performance state, MIDI routing and visual presentation.

Determinism

Repeatable behaviour matters because Harmonic is meant to be learned like an instrument. The same input and state should produce the same musical result.

Tonal systems

The architecture models tonal systems explicitly so musical behaviour can expand without coupling every new scale or mode directly to the interface.

Output independence

Musical roles are derived and routed independently, allowing different instruments to perform coordinated parts.

Testing

The core engine is covered by automated tests, and development phases include regression validation.

Source availability

Harmonic is currently developed in a private repository while its product direction, distribution model and intellectual-property strategy are evaluated.
